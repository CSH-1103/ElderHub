# 11 管家分配

> 涉及代码：`controller/NurseAssignController`、`service/NurseAssignService(+impl)`、`entity/Customer`

## 1. 功能概述

管理员把客户分配给健康管家（一个管家可服务多个客户，一个客户只能有一个管家），也可以解除分配关系。

## 2. 接口清单

基础路径：`/admin/user`

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| GET | `/nurse-customers/{nurseId}` | 查某管家服务的客户 | 路径 `nurseId` | `List<Customer>` |
| POST | `/assign-customer` | 给管家分配客户 | Query：`nurseId`、`customerId` | - |
| DELETE | `/remove-customer/{customerId}` | 解除客户的管家关系 | 路径 `customerId` | - |

## 3. 核心业务逻辑（NurseAssignServiceImpl）

### 3.1 查管家客户 `listNurseCustomers(nurseId)`

条件：`customer.user_id = nurseId AND is_deleted = 0`，按 `create_time` 倒序。

### 3.2 分配 `assignCustomer(nurseId, customerId)`（事务）

1. 校验客户存在且未删除，否则抛异常（`客户不存在`）；
2. 校验客户未被分配：`user_id IS NOT NULL AND user_id != -1` 的记录存在则抛异常（`该客户已有管家，不能重复分配`）；
3. `UpdateWrapper` 更新：`user_id = nurseId`、`update_time = now`，更新条件为 `id=customerId AND is_deleted=0 AND (user_id IS NULL OR user_id=-1)`；
4. 更新行数为 0 抛异常（`分配失败，客户可能已被其他管家分配，请刷新后重试`）——并发保护。

### 3.3 解除分配 `removeCustomerAssign(customerId)`（事务）

1. 校验客户存在且未删除；
2. `user_id` 重置为 `-1`、`update_time = now`；
3. 不影响护理记录等信息。

## 4. 数据表

代码依赖 `customer.user_id` 列（约定 `-1` 表示无管家）；该列在当前建表脚本/数据库中尚未定义，见注意事项。客户基本信息见 03 文档。

## 5. 注意事项

1. 当前 `sql/08_biz_customer.sql`（以及实际 `elderhub` 库）的 `customer` 表**没有** `user_id` 列，分配/查询/解除都会失败，需要先补充该字段（如 `ALTER TABLE customer ADD COLUMN user_id int DEFAULT -1`）；
2. 管家侧接口（04/05/12 文档）查询自己客户时同样依赖该字段；
3. 分配动作本身不做角色校验（不校验 `nurseId` 是否真的是 `role_id=2` 的管家）。
