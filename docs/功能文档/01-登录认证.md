# 01 登录认证

> 涉及代码：`controller/AuthController`、`service/UserService(+impl)`、`utils/JwtUtil`、`interceptor/JwtInterceptor`、`annotation/RequireLogin`、`dto/LoginUser`、`dto/UserContext`

## 1. 功能概述

提供注册、登录、登出接口。登录成功后签发 JWT，前端在后续请求头中携带 `Authorization: Bearer <token>`；后端通过拦截器+注解校验登录态，并把当前用户放入 `ThreadLocal` 供业务使用。

## 2. 接口清单

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| POST | `/auth/register` | 注册 | JSON：`{username, password}` | `{id, username}` |
| POST | `/auth/login` | 登录 | JSON：`{username, password}` | `{userId, username, token, role}` |
| POST | `/auth/logout` | 登出（需登录） | - | - |

> 完整路径带上下文：`http://localhost:8080/ElderHub/auth/login`。

## 3. 核心流程

### 3.1 注册 `AuthController.register → UserServiceImpl.register`

1. 校验用户名、密码非空（`IllegalArgumentException`：`Username is required` / `Password is required`）；
2. 按 `username` 查重，已存在抛 `Username already exists`；
3. 新建 `User`：仅写入 `username`，密码用 `BCryptPasswordEncoder` 加密后写 `password`；
4. 返回 `id` 与 `username`。

### 3.2 登录 `AuthController.login → UserServiceImpl.login`

1. 按 `username` 查询用户，不存在抛 `User not found`；
2. `passwordEncoder.matches()` 校验密码，错误抛 `Invalid password`；
3. 解析角色名：`role_id=1` → `ADMIN`，否则 `USER`；若 `role` 表能查到该 `role_id`，则以 `role.name` 覆盖；
4. 调用 `JwtUtil.generateToken(userId, username, roleName)` 生成 Token；
5. 返回 `userId、username、token、role`。

### 3.3 JWT（`utils/JwtUtil`）

| 方法 | 说明 |
| --- | --- |
| `generateToken(userId, username, roleName)` | HS256 签名；`sub=userId`，claims：`username`、`roleName`；`exp = now + expiration-ms` |
| `parseToken(token)` | 验签并解析出 `Claims` |
| `validateToken(token)` | 解析成功返回 `true`，否则 `false` |

密钥与有效期来自 `application.yml` 的 `jwt.secret`、`jwt.expiration-ms`（默认 86400000ms）。

### 3.4 拦截器与登录态

- `JwtInterceptor.preHandle`：
  1. `OPTIONS` 请求直接放行（CORS 预检）；
  2. 仅当被调方法带 `@RequireLogin` 注解时才校验；否则直接放行；
  3. 取 `Authorization` 头，必须 `Bearer ` 开头，否则返回 401（JSON：`{"code":401,...}`）；
  4. `validateToken` 失败同样返回 401；
  5. 成功则解析 `userId、username`，`UserContext.set(new LoginUser(userId, username))`。
- `afterCompletion` 调用 `UserContext.clear()` 防止线程复用串数据。
- `UserContext` 内部为 `ThreadLocal<LoginUser>`，提供 `set/get/clear`。

### 3.5 登出

JWT 无状态，服务端不维护会话；`/auth/logout` 直接返回成功，前端收到后清除本地 Token 即可。

## 4. 数据表

`user`（系统用户表，01_sys_user.sql）：`id、nickname、username、password、sex(0女1男)、email、phone_number、role_id、create_time、create_by、update_time、update_by、is_deleted`。

## 5. 注意事项

1. 当前 `@RequireLogin` 只标注在 `/auth/logout` 上，其余接口默认不校验登录态；如需整体鉴权需给对应方法补注解。
2. 登录返回的 `role` 用于前端菜单展示；后端接口未按角色做访问控制（`/admin/**` 与 `/nurse/**` 仅靠路径区分）。
3. 注册只写 `username/password`，其余字段依赖数据库默认值；`saveUser`（用户管理）目前**未加密密码**（代码中留有 TODO）。
