# 12 管家日常护理

> 涉及代码：`controller/NurseDailyController`、`service/NurseDailyService(+impl)`、`dto/NurseRecordAddDTO`、`vo/CustomerNurseItemVO|NurseRecordVO`

## 1. 功能概述

健康管家端接口：查看自己服务的客户、查看客户已购护理项目（含状态）、录入护理记录（校验归属与剩余次数后扣减）、查看护理记录。全部接口要求"客户属于当前管家"。

## 2. 接口清单

基础路径：`/nurse`

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| GET | `/customer/list` | 管家服务客户分页 | `pageNum=1`、`pageSize=10`、`customerName`（可空）、`userId` | `IPage<Customer>` |
| GET | `/customer/items/{customerId}` | 客户已购项目（含状态） | 路径 `customerId`、Query `userId` | `List<CustomerNurseItemVO>` |
| POST | `/nurse-record/save` | 录入护理记录 | JSON：`NurseRecordAddDTO`、Query `userId` | - |
| GET | `/nurse-record/list/{customerId}` | 客户护理记录 | 路径 `customerId`、Query `userId` | `List<NurseRecordVO>` |

> `userId` 目前由前端传入（默认值 1），接入 JWT 后应从 `UserContext` 取当前登录用户。

## 3. 核心业务逻辑（NurseDailyServiceImpl）

### 3.1 服务客户分页 `listMyCustomers`

条件：`user_id = userId AND is_deleted = 0`，`customerName` 模糊（`customer_name like`），按 `create_time` 倒序。

### 3.2 客户已购项目 `listCustomerItems(customerId, userId)`

1. **归属校验** `checkCustomerOwnership`：
   - 客户不存在或已删除 → `客户不存在`；
   - `customer.user_id != userId` → `无权操作该客户，该客户不属于您服务`；
2. 查 `customer_nurse_item`（`is_deleted=0`，按 `create_time` 倒序），批量补项目名称/编号/价格；
3. 计算状态（本模块语义）：

| status | statusDesc | 判断 |
| --- | --- | --- |
| 2 | 已到期 | `maturityTime < 今天` |
| 3 | 次数不足 | `nurseNumber` 为空或 `<= 0` |
| 1 | 正常 | 其他情况 |

### 3.3 录入护理记录 `saveNurseRecord(dto, userId)`（事务）

1. 归属校验；
2. 校验 `nursingCount > 0`，否则抛异常（`护理次数必须大于0`）；
3. 查客户该项目购买记录（`customer_id + item_id + is_deleted=0`），不存在抛异常（`客户未购买该护理项目`）；
4. 校验剩余次数：`nurse_number >= nursingCount`，否则抛异常（`该项目剩余次数不足，剩余：x次`）；
5. 插入 `nurse_record`：`user_id = userId`（当前管家）、`nursing_time`（传了用传入值，否则 now）、内容与次数；
6. 通过 `UpdateWrapper` 补写 `create_time/update_time = now`；
7. 扣减：`nurse_number = 原数量 - nursingCount`，并更新 `update_time`。

### 3.4 客户护理记录 `listNurseRecords(customerId, userId)`

1. 归属校验；
2. 按客户查 `nurse_record`（`is_deleted=0`，按 `nursing_time` 倒序），补项目名（`nursingName`）。

## 4. 数据表

| 表 | 关键字段 |
| --- | --- |
| `customer` | `id、customer_name、user_id(管家)、is_deleted、create_time` |
| `customer_nurse_item` | `id、customer_id、item_id、nurse_number、buy_time、maturity_time、is_deleted` |
| `nurse_record` | `id、customer_id、item_id、user_id、nursing_time、nursing_content、nursing_count、is_deleted` |

## 5. 注意事项

1. 与 10 文档的管家接口存在**重复映射**（`POST /nurse/nurse-record/save`、`GET /nurse/nurse-record/list/{customerId}`），启动时会 Ambiguous mapping，需要合并保留一套（本模块的实现更完整，建议保留本套）；
2. 状态语义与 09 文档（客户护理设置）不一致（`2/3` 含义互换），建议统一；
3. `customer.user_id` 列在当前建表脚本中缺失，需补充；
4. `create_time/update_time` 是通过 `UpdateWrapper` 单独补写的（`NurseRecord` 实体无这两个字段）。
