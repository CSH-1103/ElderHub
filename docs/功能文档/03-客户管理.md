# 03 客户管理

> 涉及代码：`controller/CustomController`、`service/CustomerService(+impl)`、`entity/Customer`、`entity/Bed|BedDetails`

## 1. 功能概述

管理在住老人（客户）信息：入住登记、修改、删除，以及简单的"外出/回院"床位状态切换。

## 2. 接口清单

基础路径：`/admin/customer`

| 方法 | 路径 | 说明 | 入参 | 返回 |
| --- | --- | --- | --- | --- |
| POST | `/save` | 入住登记 | JSON：`Customer` | `Result<Void>` |
| PUT | `/update` | 修改客户 | JSON：`Customer`（含 id） | `Result<Void>` |
| DELETE | `/remove/{id}` | 删除客户 | 路径 id | `Result<Void>` |
| POST | `/goOut/{id}` | 老人外出（床位→外出） | 路径 id | `Result<Void>` |
| POST | `/comeback/{id}` | 老人回院（床位→已入住） | 路径 id | `Result<Void>` |
| GET | `/no-nurse` | 无床位/无管家客户列表 | - | `Result<List<Customer>>` |

## 3. 核心业务逻辑（CustomerServiceImpl，均带事务）

### 3.1 入住登记 `saveCustomer`

1. 校验：`expiration_date` 不得早于 `checkin_date`（否则抛异常→接口返回 500）；
2. 按 `birthday` 计算年龄：`Period.between(birthday, today).getYears()`（**忽略传入的 `customer_age`**，且 `birthday` 不能为空）；
3. 校验床位：`bed_id` 对应床位存在且 `bed_status = 1`（空闲），否则抛异常；
4. 插入 `customer`；
5. 更新床位 `bed_status = 2`（已入住）；
6. 插入 `bed_details`：`start_date = checkin_date`、`end_date = null`（入住历史）。

### 3.2 修改客户 `updateCustomer`

1. 校验客户存在；
2. 若同时传了 `expiration_date` 与 `checkin_date`，校验到期日不早于入住日；
3. 若**到期日期发生变化**：查询该客户当前生效的 `bed_details`（`end_date IS NULL`，取 1 条），把其 `end_date` 更新为新的 `expiration_date`；
4. `updateById` 更新客户。

### 3.3 删除客户 `removeCustomer`

1. 校验客户存在；
2. `removeById(id)` 删除客户（代码按"逻辑删除"注释，见注意事项）；
3. 对应床位恢复 `bed_status = 1`（空闲）；
4. 当前生效的 `bed_details`（`end_date IS NULL`）执行 `deleteById`。

### 3.4 外出 / 回院

- `goOut(id)`：客户必须有床位且床位状态为 **2（已入住）**，改为 **3（外出）**；
- `comeback(id)`：床位状态必须为 **3（外出）**，改回 **2（已入住）**。

### 3.5 无管家客户列表 `listNoNurse`

当前实现：`bed_id IS NULL`，按 `checkin_date` 倒序返回（代码注释为"管家ID为空"，与实现不一致，见注意事项）。

## 4. 数据表

| 表 | 关键字段 |
| --- | --- |
| `customer` | `id、customer_name、customer_age、customer_sex(0男1女)、idcard、room_no、building_no、bed_id、checkin_date、expiration_date、contact_tel、birthday、height、weight、blood_type、psychosomatic_state、attention、filepath、is_deleted` |
| `bed` | `id、bed_no、room_no、bed_status(1空闲2已入住3外出)、remarks` |
| `bed_details` | `id、bed_id、customer_id、start_date、end_date、bed_details、is_deleted` |

## 5. 注意事项

1. **删除为物理删除**：项目未配置 `@TableLogic` 或全局逻辑删除（`application.yml` 无 `logic-delete-*`），`removeById/deleteById` 实际执行物理删除；仅 `User`、`NurseContent` 等模块用"置 `is_deleted=1`"手工实现逻辑删除；
2. 入住登记未强制写入 `building_no`（楼栋固定值 `606` 在床位调换逻辑中才写入），需要前端传值；
3. `listNoNurse` 实际过滤条件为 `bed_id IS NULL`，如需求是"无管家客户"应改用管家字段过滤（需数据库有对应列）；
4. 接口在 Service 抛错时由 Controller `catch` 后用 `Result.error(e.getMessage())` 返回（code=500），异常消息直接透出前端。
