# 04 退住管理

> 涉及代码：`controller/BackDownController`（管理员）、`controller/NurseBackDownController`（管家）、`service/BackdownService(+impl)`、`entity/Backdown`、`dto/BackDownAddDTO|BackDownQuery`、`vo/BackDownVO`

## 1. 功能概述

管家为客户提交退住申请，管理员审核；审核通过后按退住类型决定是否释放床位。退住类型：正常退住、死亡退住、保留床位。

## 2. 接口清单

管理员（`/admin/back-down`）：

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| GET | `/list` | 分页查询（客户姓名模糊） | Query：`customerName`、`pageNum=1`、`pageSize=10` | `PageResult<BackDownVO>` |
| PUT | `/audit` | 审核 | Query：`id`、`auditStatus`(1 同意 / 2 拒绝)、`auditPerson` | - |

管家（`/nurse/back-down`）：

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| POST | `/save` | 提交退住申请 | JSON：`BackDownAddDTO` | - |
| GET | `/list` | 查询自己客户的退住申请 | Query：`customerName`、分页参数、`userId`（默认 1） | `PageResult<BackDownVO>` |

## 3. 核心业务逻辑

### 3.1 提交申请 `saveBackDown`

写入 `backdown`：`customer_id、retreattime、retreattype、retreatreason、remarks`，`auditstatus` 固定为 **0（已提交/待审核）**。

### 3.2 审核 `auditBackDown(id, auditStatus, auditPerson)`

1. 查单：不存在或 `auditstatus != 0`（已审核）时抛异常（`退住单不存在或已审核`）；
2. 更新 `auditstatus`、`auditperson`、`audittime = now`；
3. **审核通过（auditStatus=1）且退住类型为 0（正常）或 1（死亡）**：
   查客户 → 查客户床位 → 床位 `bed_status = 1`（空闲，即释放床位）；
4. 退住类型为 2（保留床位）时不改床位。

### 3.3 列表

- 管理员：`customerName` 模糊时用子查询 `custom_id IN (SELECT id FROM customer WHERE name LIKE ...)`；
- 管家：子查询 `customer_id IN (SELECT id FROM customer WHERE butler_id = {userId})`，均按 `retreattime` 倒序；
- `BackDownVO.auditTime` 由 `LocalDateTime` 转 `LocalDate`（只保留日期）。

## 4. 数据表

`backdown`（15_biz_backdown.sql）：`id、customer_id、retreattime、retreattype(0正常/1死亡/2保留床位)、retreatreason、auditstatus(0已提交/1同意/2拒绝)、auditperson、audittime、remarks、is_deleted`。

## 5. 注意事项

1. 两处模糊查询子句引用的列名（`customer.name`、`customer.butler_id`）与当前 `customer` 表实际字段（`customer_name`，且无 `butler_id`/`user_id` 列）不一致，联调前需统一（改代码或补字段）；
2. 管家查询的 `userId` 目前由前端传入（默认 1），未接 JWT 后应改为从 `UserContext` 获取；
3. 审核不通过（2）不释放床位。
