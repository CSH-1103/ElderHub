# 05 外出管理

> 涉及代码：`controller/OutwardController`（管理员）、`controller/NurseOutwardController`（管家）、`service/OutwardService(+impl)`、`entity/Outward`、`dto/OutwardAddDTO|OutwardQuery`、`vo/OutwardVO`

## 1. 功能概述

管家为客户提交外出申请，管理员审核；审核通过后客户床位变为"外出"，回院登记后恢复"已入住"。

## 2. 接口清单

管理员（`/admin/outward`）：

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| GET | `/list` | 分页查询（客户姓名模糊） | Query：`customerName`、`pageNum=1`、`pageSize=10` | `PageResult<OutwardVO>` |
| PUT | `/audit` | 审核 | Query：`id`、`auditStatus`(1 同意 / 2 拒绝)、`auditPerson` | - |

管家（`/nurse/outward`）：

| 方法 | 路径 | 说明 | 入参 | 返回 data |
| --- | --- | --- | --- | --- |
| POST | `/save` | 提交外出申请 | JSON：`OutwardAddDTO` | - |
| GET | `/list` | 查询自己客户的外出申请 | Query：分页参数、`customerName`、`userId`（默认 1） | `PageResult<OutwardVO>` |
| PUT | `/return` | 登记回院 | Query：`id` | - |

## 3. 核心业务逻辑

### 3.1 提交申请 `saveOutward`

写入 `outward`：`customer_id、outgoingreason、outgoingtime、expectedreturntime、escorted、relation、escortedtel、remarks`，`auditstatus` 固定 **0（已提交）**。

### 3.2 审核 `auditOutward(id, auditStatus, auditPerson)`

1. 记录不存在或不是待审核（`auditstatus != 0`）→ **静默返回**（不报错不更新）；
2. 更新 `auditstatus、auditperson、audittime=now`；
3. **审核通过（1）**：查客户与床位，`bed_status = 3`（外出）。

### 3.3 回院登记 `registerReturn(id, actualReturnTime)`

1. 记录不存在 → 抛异常 `外出记录不存在`；
2. 实际回院时间取**服务器当前时间**（`LocalDateTime.now()`，接口不接收时间参数）；
3. 客户床位状态恢复为 `2`（已入住）。

### 3.4 列表

- 管理员：`customerName` 模糊 → 子查询 `customer_id IN (SELECT id FROM customer WHERE name LIKE ...)`；
- 管家：子查询 `customer_id IN (SELECT id FROM customer WHERE butler_id = {userId})`，均按 `outgoingtime` 倒序。

## 4. 数据表

`outward`（14_biz_outward.sql）：`id、customer_id、outgoingreason、outgoingtime、expectedreturntime、actualreturntime、escorted、relation、escortedtel、auditstatus(0已提交/1同意/2拒绝)、auditperson、audittime、remarks、is_deleted`。

## 5. 注意事项

1. 与退住模块相同：模糊查询/管家过滤引用的 `customer.name`、`customer.butler_id` 与当前表结构不一致，联调前需统一；
2. `convertToPageResult` 中 `customerId` 被赋值两次（先 `d.getId()` 后 `d.getCustomer_id()`，最终取后者）；`customerName` 未填充（注释说明需前端/联表补充）；
3. 审核非待审核记录静默成功（返回 code=200），与退住模块抛异常的行为不同；
4. 管家 `userId` 目前由前端传入，后续应改为 `UserContext` 获取。
